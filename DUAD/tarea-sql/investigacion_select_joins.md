# Research: ORDER BY, LIMIT, GROUP BY and JOINs

| Clause / Operator | What it does | Basic syntax | Example | When to use it |
|---|---|---|---|---|
| **ORDER BY** | Sorts the rows of the result by one or more columns, ascending (`ASC`, default) or descending (`DESC`). | `SELECT columns FROM table ORDER BY column [ASC\|DESC];` | `SELECT Name, Author FROM Books ORDER BY Name ASC;` | When results need to be presented in a specific order, e.g. an alphabetical listing, a ranking, or most-recent-first records. |
| **LIMIT** | Restricts how many rows the query returns. Can be combined with `OFFSET` to skip a number of rows before returning results (pagination). | `SELECT columns FROM table LIMIT n [OFFSET m];` | `SELECT Name FROM Books ORDER BY Name LIMIT 3;` | To paginate results, show a "top N" (the 5 best-selling products), or simply sample data from a large table without pulling everything. |
| **GROUP BY** | Groups rows that share the same value in one or more columns, so aggregate functions (`COUNT`, `SUM`, `AVG`, `MAX`, `MIN`) can be applied to each group. | `SELECT column, AGGREGATE_FUNCTION(column2) FROM table GROUP BY column;` | `SELECT AuthorID, COUNT(*) FROM Books GROUP BY AuthorID;` | When totals or summaries per category are needed, e.g. how many books each author wrote, or total sales per month. |
| **INNER JOIN** | Combines rows from two tables when a match exists on the relating column in **both** tables. If there's no match, the row is left out of the result. | `SELECT columns FROM tableA INNER JOIN tableB ON tableA.id = tableB.id_fk;` | `SELECT Books.Name, Authors.Name FROM Books INNER JOIN Authors ON Books.Author = Authors.ID;` | When only records with a full relationship on both sides matter, e.g. books that do have a registered author. |
| **LEFT JOIN** | Returns **all** rows from the left table, along with matching columns from the right table when a match exists; if not, those columns come back as `NULL`. | `SELECT columns FROM tableA LEFT JOIN tableB ON tableA.id = tableB.id_fk;` | `SELECT Books.Name, Authors.Name FROM Books LEFT JOIN Authors ON Books.Author = Authors.ID;` | When you want to keep every record from the main table even without a relationship, e.g. listing all books even if some have no author assigned, or finding "orphan" records (books without an author) by filtering on `NULL`. |
| **RIGHT JOIN** | The mirror of `LEFT JOIN`: returns **all** rows from the right table, along with matching columns from the left table when a match exists; if not, they come back as `NULL`. | `SELECT columns FROM tableA RIGHT JOIN tableB ON tableA.id = tableB.id_fk;` | `SELECT Books.Name, Authors.Name FROM Books RIGHT JOIN Authors ON Books.Author = Authors.ID;` | When you want to keep every record from the "secondary" table, e.g. listing all authors even if they have no books registered. In practice it can almost always be rewritten as a `LEFT JOIN` by swapping the table order, which is why some engines (like older versions of SQLite) didn't support it directly. |

## Additional notes

- **Logical execution order**: in a query with several clauses, SQL processes them in this order: `FROM/JOIN` → `WHERE` → `GROUP BY` → `HAVING` → `SELECT` → `ORDER BY` → `LIMIT`. That's why `ORDER BY` and `LIMIT` go at the end of the query, and `GROUP BY` can be paired with `HAVING` to filter already-aggregated groups.
- **JOINs and NULL**: both `LEFT JOIN` and `RIGHT JOIN` are useful for detecting missing relationships: if a column from the "optional" table comes back as `NULL` after the join, it means there was no match (e.g. `WHERE Authors.ID IS NULL` to find books without an author).
- **FULL OUTER JOIN** (not listed in the table above since it wasn't requested) combines both behaviors: it keeps unmatched rows from both tables. SQLite has supported it since version 3.39.
